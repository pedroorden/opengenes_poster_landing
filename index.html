AI-Based Extraction of Structured Lifespan Data from Scientific Literature

Rafikova E1,2, Orden PD2, Nemirovich-Danchenko N2, Duhart JM1, Buslje CM1, Ceriani MF1

1 Fundación Instituto Leloir, Buenos Aires, Argentina · 2 Open Longevity, Sherman Oaks, CA, USA

Curating Open Genes means reading each article, its supplementary material and its figures to record every lifespan experiment in 51 structured fields. This pipeline automates that reading: a multimodal language model extracts and justifies each field, a vision model with code execution measures survival curves, and a code layer checks every quote against the document, applies the Open Genes guideline and abstains when a value has no evidence.

Multimodal

Text, tables and images. Curves are measured on the figure image; text inside figures is recovered by OCR to verify quotes.

Verification and abstention

The model must quote its evidence, and code searches for that quote in the document. In sensitive fields, a value without verified evidence is left as “not reported”.

Guideline rules in code

The Open Genes conventions that can be formalised are applied deterministically, not delegated to the model.

Subpipelines

Inside each step

1

Document preparation and supplementary reader

Before any model call, code prepares the article text and everything useful in the supplementary material. It runs locally, at no cost. The article PDF is passed to the models whole; its text and the OCR of its figures (Tesseract, 300 dpi) are used to verify quotes and to offer cohort-size candidates.

A · Per-animal tables

docx · xlsx · pptx
  1. Table with the age at death of each animal
  2. Split by group: sex, genotype
  3. Censored animals (alive at the end) excluded
  4. Per group: n, mean, median, 10th percentile = minimum and 90th percentile = maximum lifespan

B · Other tables and text

all formats
  • Summary tables passed on without recomputing
  • Incidence and count tables as text; primer tables and tables over 150 rows skipped
  • Methods section: genotyping, housing, statistical method
  • “n = X” mentions as candidates

C · Files for the model

pdf · docx
  • Supplementary PDFs attached whole
  • Images inside Word files extracted and downscaled to 2048 px (e.g. tables pasted as images)
  • OCR of those images, used only to verify quotes

3

Survival-curve reading with code execution

When an article does not report minimum, median or maximum lifespan in the text, they are measured on the figure. The vision model does not estimate by eye: it writes and runs Python on the image.

1

Locate the figure · code

Finds the pages that mention survival and the figure number cited by enumeration, and renders them at 150 dpi. If several pages qualify, all are sent.

2

Measure · GPT with code interpreter

Discards images without a chart, calibrates the axes from the pixel position of labelled ticks, identifies each group's curve from the legend, measures the crossings at 90%, 50% and 10% survival, and reads the time unit and the n of each group.

3

Check · code

Two independent readings. Each must keep minimum ≤ median ≤ maximum. The mean is accepted if the readings differ by 15% or less; otherwise the value is left for review. Cohort sizes must match exactly.

4

Adjust · code

If the axis is time since treatment, the starting age is added to express age since birth. Readings are cached, so a figure is never paid for twice.

3.2%mean error at 10% survival with code execution, against ~23% by eye
97%of values within 5% of the reference
4

Consolidation: from model answers to a final record

Code combines the outputs of the subpipelines and decides the final value of each field.

Source priority

For lifespan values and cohort sizes. A curve reading never replaces a value the article reports and that was verified.

Text, table or legend→Per-animal data→Curve reading

Quote verification

Each quote is searched for in the PDF text, the supplementary text and the OCR of figures and images. The search tolerates the usual PDF problems: broken characters, interleaved two-column text, fragments joined with ellipses and one-character OCR errors.

Open Genes guideline rules

  • Percent changes computed from the absolute values, not taken from the model
  • Kaplan-Meier is not recorded as a test; Mantel-Cox is recorded as log-rank
  • Fold changes converted to percent with the guideline's formula
  • Heterozygotes classified as knockout
  • Protein preferred when RNA was also measured

Abstention

In sensitive fields (cohort sizes, lifespan values, expression, statistical method) a value without evidence becomes nsp. The discarded value and the reason are kept.

Row curation

Rows outside the Open Genes criteria are set apart with their reason: more than one intervention, a genetically modified control, a rescue or inactive construct, a duplicate control arm.

Review flagging

Fields with medium or low confidence and unstable curve readings are flagged for the curator. Values outside the allowed vocabulary are flagged as “new value”.

Validation

Measured against curators, reviewed by curators

Every run is compared with records curated by hand by the Open Genes team, and a curator reviews the disagreements. Each review feeds back into the pipeline and into the reference itself.

How fields are compared

  • Experiment matching by optimal assignment (Hungarian algorithm), so nearly identical experiments (same line, different sex) are not crossed.
  • Exact match after normalising case, dashes and domain synonyms.
  • Open Genes tolerance: 5% on lifespan values, 10% on percent changes in lifespan and expression.
  • List fields (vital processes, statistical methods) also report partial agreement (Jaccard index).

Automatic error diagnosis

Every model call is traced: prompt, attached files, response, tokens and cost. At the end of a run, each disagreement is classified from those traces:

  1. Correct model value discarded by a pipeline filter
  2. Curve-reading error, or figure not located
  3. Percent change computed from values with errors
  4. Value absent from all the text given to the model
  5. Value in the text, different answer from the model
  6. Judgement or list field

Limitations

  • Evaluated on 20 articles (47 experiments) and a single reference table, which also contains errors.
  • Some judgement fields (vital processes, significance of a specific metric) still lack a written Open Genes criterion.
  • Figures inside supplementary PowerPoint files are not read yet.
  • The models are commercial services; results vary by about one point between runs.

Next

  • Better reading of supplementary files, the main remaining gap.
  • Validation on all 368 lifespan articles in Open Genes.
  • Search and download of new articles.
  • A service that delivers records to the Open Genes curation workflow; open-source models run locally under evaluation.
