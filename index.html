Open Genes

Manually curated database of genes associated with aging and lifespan. This pipeline reads an article, its supplementary material and its figures, and writes each lifespan experiment as an Open Genes record, with the evidence for every value.

1. Extraction pipeline, step by step

Code decides the order of the steps, how sources are combined and the final value of each field. The models have fixed roles and do not interact with each other: it is not a multi-agent system.

3. Subpipelines

The parts of the system that do the detailed work.

Supplementary reader

Before any model call, code prepares everything that can be prepared without AI. It runs locally, at no cost. The article PDF goes to the models whole; its text and the OCR of its figures are used to verify quotes and to offer cohort-size candidates.

A · Per-animal tables

docx · xlsx · pptx

  1. Age at death of each animal
  2. Split by sex and genotype
  3. Censored animals (alive at the end) excluded
  4. Per group: n, mean, median, 10th percentile = minimum and 90th percentile = maximum lifespan

B · Other tables and text

all formats

  • Summary tables passed on as they are
  • Incidence and count tables as text; primer tables and tables over 150 rows skipped
  • Methods: genotyping, housing, statistical method
  • “n = X” mentions as candidates

C · Files for the model

pdf · docx

  • Supplementary PDFs attached whole
  • Images inside Word files (e.g. tables pasted as images) extracted and attached
  • OCR of those images, only to verify quotes
All of it reaches every Gemini call: a context block with the instruction to check each data point against the experiment, plus the attached files.

Extraction with Gemini: four calls

The article PDF and the supplementary material go to all four calls. Transient errors are retried up to three times; an experiment that still fails is reported without stopping the rest of the article.

1 · Experiment enumeration · temperature 0

ReceivesInclusion rules: one intervention on the gene, a control without genetic modification, each sex, line or age is a separate experiment
DoesReads the whole article and identifies the valid comparisons
ReturnsThe experiments and the curve figure of each, or the reason none is valid

2 · Paper-level facts · once per article

ReceivesThe fields that apply to the whole article
DoesLooks for the general data in methods and results
ReturnsOrganism, diet, temperature, density, statistical method, classification and expression change of each intervention

3 · Extraction · one call per experiment

ReceivesThe experiment, the paper-level facts, rules and vocabulary of the 51 fields, a solved example from another article with the same type of intervention, cohort-size candidates
DoesFills in the 51 fields of that experiment
Returns, per fieldValue, rejected alternatives and why, quote with page and section, reasoning, confidence, review flag

4 · Missing fields · only when needed

ReceivesOnly the fields call 3 left unanswered
DoesLooks for them in the same format
ReturnsThe missing fields with value, quote and confidence

Reading survival curves

When an article does not write minimum, median or maximum lifespan, they are measured on the figure. The vision model does not estimate by eye: it writes and runs Python on the image.

  1. Locate · code finds the pages that mention survival and the figure cited by enumeration, and renders them as images.
  2. Calibrate · GPT finds the pixel position of the labelled ticks and builds the time scale.
  3. Identify · each group's curve, from the legend.
  4. Measure · where each curve crosses 90%, 50% and 10% survival: minimum, median and maximum lifespan.
  5. Read · the time unit, the n of each group and the sex.
  6. Check · two independent readings; each must keep minimum ≤ median ≤ maximum, and they must agree, or the value is left for review. Cohort sizes must match exactly.

If the axis is time since treatment, code adds the starting age to express age since birth. Readings are cached, so a figure is never paid for twice.

97% of values within 5% of the referenceMean error at 10% survival: 3.2% with code execution, against ~23% by eye.

Consolidation

Code combines the outputs of the subpipelines and decides the final value of each field.

  1. Source priority

    For lifespan values and cohort sizes. A curve reading never replaces a value the article writes and that was verified.

    Text, table or legend→Per-animal data→Curve reading

  2. Quote verification

    Each quote is searched for in the PDF text, the supplementary text and the OCR of figures and images, tolerating broken characters, two-column text, fragments joined with ellipses and one-letter OCR errors.

  3. Open Genes guideline rules

    • Percent changes computed from the absolute values
    • Kaplan-Meier is not recorded as a test; Mantel-Cox is recorded as log-rank
    • Fold changes converted to percent with the guideline's formula
    • Heterozygotes classified as knockout; protein preferred when RNA was also measured

  4. Abstention

    In sensitive fields (cohort sizes, lifespan values, expression, statistical method) a value without evidence becomes nsp.

  5. Row curation

    Rows outside the Open Genes criteria are set apart with their reason: more than one intervention, a genetically modified control, a rescue or inactive construct, a duplicate control arm.

  6. Review flags

    Medium or low confidence, unstable curve readings and values outside the allowed vocabulary are flagged for the curator.

4. Validation

Every run is compared with records curated by hand by the Open Genes team, and a curator reviews the disagreements. Each review corrects the pipeline and, when needed, the reference itself.

Reference

Curators read each article: 191 experiments, guideline and controlled vocabulary

Pipeline run

20 articles, 47 reference experiments

Automatic evaluation

Experiment matching, field comparison with tolerances, error diagnosis

Curator review

Every disagreement classified in the review spreadsheet

Corrections

New rules and data sources in the pipeline; fixes to the guideline and the table

The next run starts from the corrected pipeline and the corrected reference.

How fields are compared

  • Experiment matching by optimal assignment (Hungarian algorithm), so nearly identical experiments (same line, different sex) are not crossed.
  • Exact match after normalising case, dashes and domain synonyms.
  • Open Genes tolerance: 5% on lifespan values, 10% on percent changes.
  • List fields also report partial agreement (Jaccard index).

Automatic error diagnosis

Every model call is traced: prompt, files, response, tokens and cost. Each disagreement is classified from those traces:

  1. a correct value discarded by a filter
  2. curve-reading error, or figure not found
  3. % change computed from values with errors
  4. value absent from everything the model received
  5. value in the text, different answer from the model
  6. judgement or list field

Limitations

  • Evaluated on 20 articles (47 experiments) and one reference table, which also has errors.
  • Some judgement fields (aging-related processes, significance of a specific metric) still lack a written Open Genes criterion.
  • Figures inside supplementary PowerPoint files are not read yet.
  • The models are commercial services; results vary by about one point between runs.

Next

  • Better reading of supplementary files, the main remaining gap.
  • Validation on all 368 lifespan articles in Open Genes.
  • Search and download of new articles.
  • Integration into the Open Genes curation workflow; open-source models run locally under evaluation.
